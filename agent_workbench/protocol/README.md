# Batch protocol (v1)

A batch is a self-contained research task handed to a disposable external
agent. Batches are generated by the private catbalony repo and published
here read-only.

## Batch file (`batch.json`)

| field | meaning |
|---|---|
| `schema_version` | protocol version (currently 1) |
| `batch_id` | deterministic content hash (`bw-` + 12 hex); mutable bookkeeping fields are excluded from the hash |
| `title` | human-readable task title |
| `task_type` | coarse task class (e.g. `public-data-research`) |
| `status` | `ACTIVE`, `COMPLETED`, or `CANCELLED` |
| `public_path` | public destination path inside this repo's `agent_workbench/` |
| `worker_prompt` | the EXACT prompt the worker receives, including the mandatory briefing |
| `evidence_manifest` | named references (`ref`) to public material in this repo; optionally `note` |
| `output_expectations` | `format` (`markdown`, `text`, `json`) and `notes` |

`prompt.txt` in each batch folder is the same text as `worker_prompt`,
provided verbatim for convenience.

## Mandatory worker briefing

Every `worker_prompt` starts with this briefing (it is part of the prompt
text, not a side document):

```text
WORKER BRIEFING (mandatory; applies to everything below):
- At the top of your return, identify yourself: model, provider/platform,
  and mode (e.g. "agent" or "chat"). If you are uncertain about what you
  are running as, say "unknown" rather than guessing - some platforms
  route or obscure models, and your self-report is recorded but not
  treated as authoritative.
- This is RESEARCH, NOT proof authority. Your output never changes this
  project's canonical truth by itself; only the project's own
  deterministic verification can establish anything as PROVEN.
- Label every claim as exactly one of:
    OBSERVATION - you directly saw or measured it
    INFERENCE   - you concluded it from observations (say from which)
    HYPOTHESIS  - speculation, not yet grounded
- Never state or imply a canonical PROVEN status for any claim.
- If your time, context, or resources are running out, STOP and return a
  useful PARTIAL result immediately. A partial answer that arrives is
  worth more than a complete answer that never does.
```

## Returns

- Responses are returned through the operator (paste/file drop); the
  private side preserves them **byte-for-byte** before any parsing.
- The briefing asks you to **self-identify** (model / provider / mode) at
  the top of your return. Self-reported identity is recorded separately
  from operator and platform metadata and is never treated as
  authoritative - some platforms route or obscure models.
- A return is tagged `COMPLETE`, `PARTIAL`, `FAILED`, or `UNPARSED`.
- Returns whose declared `batch_id` does not match the filing target are
  rejected, never silently attached elsewhere.
- Only returns explicitly allowlisted for publication appear in this
  public tree. Externally produced content never modifies canon.
